# 云顶之弈动态辅助Agent 产品需求文档（PRD）

> 版本：v1.0 | 日期：2026-08-22 | 适用赛季：TFT Set 17（星神/Space Gods）及后续赛季

---

## 一、项目概述

### 1.1 项目背景
云顶之弈（TFT）是一款信息密度极高的自走棋游戏。单局内玩家需要同时处理：阵容规划、经济运营、装备合成、站位调整、对手counter、特殊机制适配（观星者星座/奇遇）等数十个决策点。现有辅助工具（TFT Overlay、JinChanChanTool等）多为**静态数据展示**，缺乏基于实时对局状态的**动态决策推理**能力。

本项目旨在构建一个**实时感知对局状态 + 联网获取大数据 + AI决策推理**的动态辅助Agent，在每回合为玩家提供可执行的最优决策建议。

### 1.2 核心定位
- **不是外挂**：不注入游戏进程、不自动操作，仅做信息采集与决策建议
- **不是静态攻略**：基于实时对局状态动态推理，而非固定阵容推荐
- **是"副驾驶"**：玩家做最终决策，Agent提供数据支撑与建议

## 二、核心目标

| 目标维度 | 具体指标 |
|---------|---------|
| 决策覆盖 | 覆盖商店买牌、D牌时机、升级时机、装备合成、强化选择、站位、变阵7大决策场景 |
| 数据时效 | 外部大数据延迟≤30分钟，对局状态识别延迟≤1秒 |
| 建议准确率 | Top3阵容推荐命中率≥70%（对比OP.GG同期数据），装备推荐合理率≥85% |
| 性能 | 单回合决策推理≤500ms，内存占用≤500MB，CPU占用≤15% |
| 合规 | 纯屏幕采集+外部数据，不读内存、不注入、不模拟点击，零封号风险 |

## 三、用户画像与使用场景

### 3.1 用户分层
| 用户类型 | 特征 | 核心需求 |
|---------|------|---------|
| 新手玩家 | 刚接触，记不住羁绊/装备/阵容 | 阵容推荐、装备合成提示、基础运营指引 |
| 进阶玩家 | 了解基础，想冲分 | 经济最优解、变阵时机、对手counter、强化选择 |
| 高端玩家 | 大师以上，追求极限 | 站位微调、冷门阵容挖掘、版本meta实时跟踪 |
| 主播/内容创作者 | 需要数据支撑 | 赛后数据复盘、阵容胜率统计、可视化 |

### 3.2 典型使用场景
1. **开局阶段（1-1至2-5）**：识别奇遇+观星者星座→推荐开局阵容路线→提示买哪些打工棋子
2. **选秀阶段**：根据已有装备和目标阵容→推荐优先抢的装备/棋子
3. **强化符文阶段（2-1/3-2/4-2）**：根据当前阵容方向+外部数据胜率→推荐强化选择
4. **每回合商店阶段**：实时分析5个候选棋子→买/不买/D牌建议
5. **中后期（4-5以后）**：分析对手阵容→counter站位/变阵建议
6. **赛后**：复盘决策质量，输出改进建议

## 五、数据输入层 — 实时对局状态采集

### 5.1 采集方式（三选一或组合）

| 方式 | 原理 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| **屏幕OCR+图像识别**（推荐主力） | 截取游戏窗口，OCR识别文字+模板匹配识别棋子/装备图标 | 纯外部，零封号风险，兼容性强 | 识别准确率受分辨率/UI变化影响 | 无 |
| **游戏日志解析** | 读取游戏本地日志文件（如`League of Legends/Logs`） | 数据精确，不依赖图像 | 日志内容有限，可能不含实时商店/对手信息 | 低（只读文件） |
| **LCU API** | 英雄联盟客户端API（`riotclient`端口） | 数据结构化、精确 | 云顶之弈对局内数据覆盖不全，需端口token | 低（官方API） |

> **推荐方案**：屏幕OCR为主，日志+LCU为辅，手动校准兜底。

### 5.2 对局基础信息
| 数据项 | 说明 | 采集方式 |
|-------|------|---------|
| 当前赛季/版本号 | Set 17 / 17.x | 启动时检测+联网确认 |
| 对局阶段 | 1-1, 2-5, 3-2等 | OCR识别左上角回合数 |
| 游戏模式 | 排位/匹配/狂暴 | OCR或LCU |
| 当前大区 | 国服/美服/韩服等 | 配置项 |
| 对局ID | 唯一标识 | LCU/日志 |

### 5.3 玩家自身状态（核心）
| 数据项 | 说明 | 精度要求 |
|-------|------|---------|
| 等级 | 当前等级（1-10） | 精确 |
| 经验值 | 当前经验/升级所需 | 精确 |
| 金币数 | 当前金币 | 精确（影响利息计算） |
| 血量 | 当前生命值 | 精确 |
| 连胜/连败 | 当前连胜或连败层数 | 精确（影响经济） |
| 场上棋子 | 位置、英雄、星级、装备 | 精确 |
| 备战区棋子 | 英雄、星级 | 精确 |
| 已拥有装备 | 散件+成品清单 | 精确 |
| 已选强化符文 | 3个强化（2-1/3-2/4-2） | 精确 |
| 已激活羁绊 | 当前场上羁绊及层数 | 推导（根据棋子） |
| 观星者星座 | 本局随机的星座效果 | OCR识别+文本匹配 |
| 本局奇遇 | 开局奇遇及后续奇遇事件 | OCR识别+文本匹配 |

### 5.4 商店与刷新（每回合动态变化）
| 数据项 | 说明 |
|-------|------|
| 5个候选棋子 | 英雄名称、费用、是否已拥有 |
| 刷新费用 | 当前D牌花费（受奇遇/强化影响） |
| 商店等级概率 | 根据等级推导各费卡概率 |
| 已刷新次数 | 本回合已D次数 |

### 5.5 对手状态监控
| 数据项 | 说明 | 采集难度 |
|-------|------|---------|
| 对手列表 | 7名对手名称 | OCR |
| 对手血量 | 每人当前血量 | OCR（记分板） |
| 对手等级 | 每人等级 | OCR（记分板） |
| 对手金币 | 估算（根据等级+阶段+经济规律） | 推导估算 |
| 对手场上棋子 | 观察期（非战斗回合可查看） | OCR+记忆 |
| 对手羁绊 | 根据棋子推导 | 推导 |
| 对手强化 | 观察期可见 | OCR+记忆 |
| 对手装备 | 观察期可见（主要C位装备） | OCR+记忆 |
| 对手站位 | 观察期记录 | OCR+记忆 |

> **关键设计**：建立对手状态记忆库，每个对手在可观察期（非战斗回合）扫描一次并缓存，战斗回合使用缓存数据。

### 5.6 特殊机制识别（Set 17重点）

#### 5.6.1 观星者（Stargazer）星座识别
每局随机一个星座，不同星座完全改变玩法：

| 星座 | 效果方向 | 对决策的影响 |
|------|---------|------------|
| 女猎手座 | 观星者攻速+治疗 | 推荐攻速流主C（霞/璐璐等），站位集中在加成格 |
| 勋章座 | 三星英雄伤害提升 | 鼓励慢D追三星，推荐低费赌狗阵容 |
| 秀山座 | 百分比生命值加成 | 推荐肉盾/前排阵容，站位利用加成格 |
| 泉水座 | （当前版本禁用） | — |
| 其他星座 | 待版本更新动态维护 | — |

**识别方式**：OCR识别开局观星者提示文本 → 匹配星座名称库 → 加载对应星座效果参数 → 注入决策引擎。

#### 5.6.2 奇遇（Encounters）识别
开局奇遇示例：黄金舞会、棱镜派对、棱镜终曲、棱镜开场、3费英雄开局、2费英雄开局、开场升级、道具组件铁砧、战利品订单、升级折扣、双重复制器等。

**识别方式**：OCR识别奇遇文本 → 匹配奇遇效果库 → 调整经济/升级/装备策略。

**对决策的影响示例**：
- 升级折扣奇遇 → 提前升级，加快上人口节奏
- 双重复制器奇遇 → 快速上8，利用复制器追高费卡
- 3费英雄开局 → 倾向3费主C阵容
- 战利品订单 → 调整装备优先级

#### 6.2.1 需采集的数据维度

```
│   ├── 登场率
│   ├── 平均排名
│   ├── 推荐装备（Top3）及对应胜率
│   ├── 推荐站位
│   └── 适配阵容
├── 装备数据 (items)
│   ├── 胜率
│   ├── 登场率

├── 强化符文数据 (augments)
│   ├── 胜率
│   ├── 登场率
│   ├── 平均排名
│   └── 适配阵容
└── 羁绊数据 (traits)
    ├── 各层数胜率
    ├── 登场率
    └── 适配英雄
```

#### 6.2.2 采集策略
- **频率**：每30分钟增量采集一次Meta阵容，每2小时全量采集英雄/装备/强化数据
- **去重**：基于数据更新时间戳，避免重复抓取
- **多语言**：OP.GG支持多语言（中/英/日/德/法），优先采集中文站，英文站兜底
- **地区差异**：支持按大区筛选（NA/EUW/KR/CN），国服玩家优先看国服+全球数据对比
- **容错**：单数据源失败时自动切换备用源，不影响核心功能

### 6.4 社区攻略采集与NLP处理

#### 6.4.1 采集流程
```
论坛/视频平台搜索 → 标题+正文提取 → 去重/去广告 → 
NLP实体识别（英雄名/装备名/羁绊名）→ 阵容结构提取 → 
可信度评分 → 入库
```

#### 6.4.2 可信度评分机制
社区内容质量参差不齐，需建立评分体系：
| 评分维度 | 权重 | 说明 |
|---------|------|------|
| 作者历史质量 | 30% | 历史攻略的准确率/点赞数 |
| 与大数据吻合度 | 30% | 推荐阵容是否与OP.GG高胜率阵容吻合 |
| 互动数据 | 20% | 点赞/收藏/评论数 |
| 内容完整度 | 10% | 是否包含装备/站位/运营节奏 |
| 时效性 | 10% | 是否为当前版本 |

> 低于阈值的社区内容不进入推荐池，仅作为参考。

### 6.5 数据缓存与更新策略

```
数据层级：
├── L1 实时数据（对局内）：内存缓存，TTL=1回合
├── L2 热数据（Meta阵容）：本地JSON缓存，TTL=30分钟
├── L3 温数据（英雄/装备/强化）：本地数据库，TTL=2小时
├── L4 冷数据（历史版本/赛季）：本地数据库，永久保存
└── L5 静态数据（Data Dragon）：版本更新时刷新
```

- **启动时**：检查本地缓存是否过期，过期则联网更新
- **对局中**：使用缓存数据，不频繁联网（避免占用带宽和延迟）
- **对局间隙**：后台静默更新数据
- **版本更新检测**：每次启动检测当前版本号，版本变更时触发全量数据更新

## 七、核心决策引擎

### 7.1 决策引擎总体设计

决策引擎采用**规则引擎 + 数据驱动 + 启发式搜索**混合架构：

```
输入：对局实时状态 + 外部大数据 + 版本平衡数据
  ↓
规则层：硬约束（金币不够不能买、等级不够不能上）
  ↓
数据层：基于胜率/登场率的候选排序
  ↓
推理层：多目标优化（胜率最大化 + 经济最优 + 风险控制）
  ↓
输出：TopN决策建议 + 置信度 + 理由说明
```

### 7.2 阵容规划与推荐

#### 7.2.1 开局阵容推荐（1-1至2-1）
**输入因子**：
- 观星者星座效果
- 开局奇遇
- 开局免费棋子/装备
- 外部Meta Top阵容
- 玩家段位（不同段位推荐不同难度阵容）

**输出**：
- Top3推荐阵容（含阵容名称、核心羁绊、主C、主坦）
- 每套阵容的胜率/登场率/难度
- 开局打工棋子建议
- 运营路线（速8/慢D/赌狗）

**推荐逻辑示例**：
```
IF 星座=勋章座(鼓励三星) → 优先推荐慢D赌狗阵容(低费主C)
IF 奇遇=3费英雄开局 → 优先推荐3费主C阵容
IF 星座=女猎手座(攻速加成) → 优先推荐攻速流ADC阵容
IF 玩家段位=钻石以下 → 优先推荐操作简单的S级阵容
IF 玩家段位=大师以上 → 可推荐冷门高上限阵容
```

#### 7.2.2 中期变阵推荐（3-2至4-5）
**触发条件**：
- 核心卡迟迟不来（D了很多次没出）
- 血量过低（需要变阵保血）
- 对手多家同行（竞争太激烈）
- 装备不匹配原阵容
- 强化符文指向其他阵容

**输出**：
- 是否建议变阵（置信度）
- 变阵目标阵容（Top2）
- 变阵过渡方案（哪些棋子留/卖）
- 变阵经济成本估算

### 7.3 商店棋子决策

每回合商店刷新后，对5个候选棋子逐个评分：

#### 7.3.1 单棋子评分模型
```
棋子得分 = 
  阵容契合度 × 0.35    （是否是目标阵容的卡）
+ 战力提升度 × 0.25    （上场后能否立即提升战力）
+ 追星价值 × 0.20      （距离三星还差几张/是否关键卡）
+ 经济成本 × 0.10      （费用是否可承受）
+ 灵活性 × 0.10         （是否多阵容通用，可打工可转型）
```

#### 7.3.2 决策输出
对每个候选棋子输出：
- **买**（强烈推荐，高亮提示）
- **可买**（备选，资金充裕时考虑）
- **不买**（不推荐）
- **打工过渡**（临时用，后期卖）

同时输出：
- 是否建议D牌（当前商店质量评分低+金币充裕+关键卡差1-2张）
- D牌期望收益估算（D多少次能出关键卡的概率）

#### 7.3.3 概率计算
基于等级对应的各费卡概率 + 卡池剩余数量，计算：
- 下一次D出目标卡的概率
- 期望D多少次能追到三星
- 同行竞争评估（有多少家也在拿同一张卡）

### 7.4 经济运营决策

#### 7.4.1 经济状态评估
```
当前金币 → 利息计算（每10金币+1利息，上限5）
当前等级+经验 → 升级所需金币
当前血量 → 容错空间（血量低需要花钱提战力）
连胜/连败 → 额外经济收益
奇遇/强化 → 经济修正（如升级折扣、利滚利）
```

#### 7.4.2 决策输出
- **升级建议**：是否现在升级、升级后能上什么棋子、升级的战力收益
- **D牌建议**：是否现在D、D多少金币、D牌目标是什么
- **存钱建议**：是否应该存钱吃利息、存到多少再花
- **节奏判断**：当前是该连胜保血还是连败养经济

#### 7.4.3 经典经济模型
| 运营风格 | 升级节奏 | D牌时机 | 适用场景 |
|---------|---------|---------|---------|
| 速8流 | 2-5升5, 3-2升6, 3-5升7, 4-1/4-2升8 | 8级大D找主C | 高费主C阵容（如95） |
| 慢D流 | 正常升级，卡50利息 | 7级慢D追三星3费 | 3费主C阵容 |
| 赌狗流 | 不升级，卡50利息 | 5/6级D追1-2费三星 | 1-2费主C阵容 |
| 连败流 | 故意连败拿经济+选秀优先权 | 3-5/4-1启动D牌 | 需要特定装备的阵容 |

### 7.5 装备分配与合成

#### 7.5.1 装备合成推荐
**输入**：当前散件清单 + 目标阵容主C/主坦 + 外部装备胜率数据
**输出**：
- 推荐合成的成品装备（Top3）及优先级
- 每件装备给哪个英雄
- 散件使用规划（哪些留着等合成，哪些直接合）

#### 7.5.2 装备分配逻辑
```
优先级排序：
1. 主C核心装备（如法系主C的法爆/科技枪，ADC的无尽/羊刀）
2. 主坦核心装备（如板甲/狂徒/龙牙）
3. 副C/功能装备（如冰心/静止法衣/圣杯）
4. 多余装备给工具人

特殊情况：
- 奇遇给的特殊装备（如战利品订单）→ 优先适配
- 光明装备/神器 → 优先级高于普通装备
- 装备不匹配 → 推荐变阵或找替代装备方案
```

#### 7.5.3 装备-英雄适配数据
从OP.GG获取每个英雄的Top推荐装备及对应胜率，作为分配依据。

### 7.6 强化符文选择

#### 7.6.1 强化推荐
**触发时机**：2-1、3-2、4-2强化选择阶段
**输入**：3个候选强化 + 当前阵容方向 + 外部强化胜率数据 + 已有强化组合
**输出**：
- 推荐选择（Top1）及理由
- 每个候选强化的胜率/平均排名
- 强化与当前阵容的契合度评分
- 选择后对阵容路线的影响（是否需要变阵）

#### 7.6.2 强化组合协同
某些强化组合有协同效应（如多个经济类强化叠加、战力类强化互补），需评估：
- 已有强化 + 候选强化的组合评分
- 是否存在"神组合"（如升级咯+明智消费）
- 是否存在冲突（如经济强化过多但战力不足）

### 7.7 站位优化

#### 7.7.1 基础站位推荐
- 根据目标阵容给出标准站位图（九宫格/六边形位置）
- 主C站位（角落/中间/侧翼）
- 主坦站位（前排/特定位置）
- 功能棋子站位（如冰心范围、静止法衣对准对方主C）

#### 7.7.2 对手counter站位
根据观察到的对手阵容，给出针对性站位：
| 对手阵容 | counter站位 |
|---------|------------|
| 刺客阵容 | 主C放角落，周围围保护棋子 |
| 法系AOE阵容 | 分散站位，避免被一波AOE |
| 单点爆发阵容 | 主坦对位，保护主C |
| 枪手/射程阵容 | 缩角站位，减少被攻击面 |
| 观星者加成格 | 主C/主坦站在加成格上 |

#### 7.7.3 观星者星座站位适配
不同星座的加成格位置不同，需动态调整站位使核心棋子站在加成格上。

### 7.8 对手分析与counter策略

#### 7.8.1 对手阵容识别
通过观察期扫描，识别每个对手的：
- 核心阵容（主C+主坦+关键羁绊）
- 主C装备
- 战力估算（基于棋子星级+装备+羁绊）
- 经济状态估算

#### 7.8.2 威胁评估
```
对手威胁等级 = 
  战力差距 × 0.4    （比你强多少）
+ 阵容克制 × 0.3    （是否counter你的阵容）
+ 血量威胁 × 0.2    （是否会在你之前出局/是否是决赛圈对手）
+ 竞争关系 × 0.1    （是否是同行抢卡）
```

#### 7.8.3 counter策略输出
- 哪些对手是主要威胁（Top3）
- 对每个威胁对手的counter建议（站位/装备/变阵）
- 是否需要卡对手的牌（买光对手需要的关键卡，减少他D到的概率）
- 决赛圈预测（最可能的前3对手）

### 7.9 特殊机制适配引擎

这是本Agent区别于普通辅助工具的核心模块。

#### 7.9.1 观星者星座适配
为每个星座建立独立的策略参数：
```python
class StargazerStrategy:
    constellation: str           # 星座名称
    empowered_hexes: List[Pos]  # 加成格位置
    bonus_type: str              # 加成类型（攻速/法强/生命/护盾等）
    bonus_value: dict            # 各观星者层数的加成数值
    recommended_carries: List    # 推荐主C
    recommended_comps: List      # 推荐阵容
    positioning_notes: str       # 站位注意事项
    econ_adjustment: dict        # 经济节奏调整
```

#### 7.9.2 奇遇适配
```python
class EncounterStrategy:
    encounter: str               # 奇遇名称
    effect: str                  # 效果描述
    level_route_adjust: dict     # 升级路线调整
    econ_adjust: dict            # 经济调整
    item_priority_adjust: List   # 装备优先级调整
    comp_tilt: List              # 倾向阵容
```

#### 7.9.3 机制组合推理
当观星者星座 + 奇遇 + 强化产生组合效应时，推理最优策略：
- 例：勋章座(鼓励三星) + 3费英雄开局 + 升级折扣 → 最优路线可能是快速上7后慢D追3费三星
- 例：女猎手座(攻速) + 战利品订单(给装备) → 优先拿ADC装备，走攻速流ADC阵容

## 九、技术架构设计

### 9.1 技术栈选型

| 模块 | 技术选型 | 理由 |
|------|---------|------|
| 桌面端框架 | Electron + React / Tauri + React | 跨平台，UI开发效率高；Tauri更轻量 |
| 屏幕采集 | Windows Graphics Capture / BitBlt | 高效截屏，低CPU占用 |
| OCR识别 | PaddleOCR / Tesseract | 中文识别准确率高，支持离线 |
| 图像匹配 | OpenCV模板匹配 / 特征匹配 | 棋子/装备图标识别 |
| 决策引擎 | Python / Rust | Python开发快，Rust性能高；核心推理可用Rust |
| 数据存储 | SQLite | 本地轻量数据库，存缓存和历史 |
| 网络请求 | aiohttp / reqwest | 异步HTTP，采集外部数据 |
| 进程通信 | WebSocket / gRPC | UI层与引擎层通信 |
| 打包分发 | NSIS / AppImage / DMG | 各平台安装包 |

### 9.3 核心数据流
```
游戏屏幕 → 截屏(30fps) → 区域裁剪 → OCR+图标匹配 → 结构化对局状态
                                                          ↓
外部数据采集 → 数据清洗 → 缓存入库 ←——————————————————→ 决策引擎
                                                          ↓
                                              决策建议(TopN+理由+置信度)
                                                          ↓
                                              UI渲染(悬浮窗/弹窗/语音)
```

### 9.4 性能优化要点
1. **截屏降频**：非关键阶段(战斗中)降低截屏频率至5fps，商店/选秀阶段提升至15fps
2. **区域识别**：只裁剪需要识别的区域（商店、状态栏、记分板），不全屏OCR
3. **增量识别**：只在状态变化时重新识别，不每帧全量识别
4. **缓存复用**：图标匹配结果缓存，相同图标不重复计算
5. **异步处理**：识别和决策在独立线程，不阻塞UI
6. **懒加载**：外部数据按需加载，不一次性加载全部

## 十、非功能需求

### 10.1 性能需求
| 指标 | 要求 |
|------|------|
| 截屏延迟 | ≤100ms |
| OCR识别延迟 | ≤500ms（单区域） |
| 决策推理延迟 | ≤500ms |
| 端到端延迟（截屏→建议显示） | ≤1.5s |
| CPU占用 | ≤15%（4核以上机器） |
| 内存占用 | ≤500MB |
| 启动时间 | ≤5s |

### 10.2 兼容性需求
- **操作系统**：Windows 10/11（主力），macOS（后续）
- **游戏分辨率**：支持1920×1080、2560×1440、3840×2160，及窗口模式
- **游戏客户端**：国服客户端、国际服客户端
- **显示缩放**：支持100%/125%/150%系统缩放
- **多显示器**：支持游戏在任意显示器

### 10.3 可用性需求
- 首次使用引导（校准分辨率、选择大区、选择段位）
- 离线模式（无网络时使用本地缓存数据，仅外部大数据功能受限）
- 一键重置校准
- 详细的使用说明和FAQ

### 10.4 可维护性需求
- 赛季更新适配：新赛季数据结构变更时，只需更新配置文件+数据采集规则，核心引擎不需大改
- 插件化架构：新的特殊机制（如新羁绊效果）以插件形式接入
- 日志系统：完整的操作日志和错误日志，便于排查问题
- 自动更新：客户端自动检测更新，一键升级

## 十一、风险与合规

### 11.1 封号风险评估
| 行为 | 风险等级 | 说明 |
|------|---------|------|
| 屏幕OCR识别 | 🟢 无风险 | 纯外部读取，不接触游戏进程 |
| 读取游戏日志文件 | 🟢 低风险 | 只读操作，不修改 |
| 使用LCU API | 🟢 低风险 | 官方提供的API |
| 悬浮窗显示 | 🟡 极低风险 | 部分反作弊可能检测置顶窗口，建议设置为"非游戏内注入"的普通窗口 |
| 自动点击/模拟操作 | 🔴 高风险 | **绝对禁止**，这是外挂行为 |
| 读内存/注入进程 | 🔴 高风险 | **绝对禁止** |

> **核心原则**：本工具是"信息辅助"而非"操作辅助"，所有决策由玩家手动执行。工具不模拟任何鼠标/键盘操作，不注入游戏进程，不读取游戏内存。

### 11.2 法律合规
- 数据采集遵守目标网站的robots.txt和使用条款
- 不存储/传输用户的游戏账号密码
- 社区内容转载注明来源
- 用户数据本地存储，不上传云端（除非用户主动开启云同步）

### 11.3 技术风险
| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 游戏UI改版导致OCR失效 | 识别准确率下降 | 快速迭代校准模板，提供手动校准功能 |
| 外部数据源网站改版/反爬 | 数据采集失败 | 多数据源冗余，单源失败自动切换 |
| 新赛季机制复杂 | 决策引擎适配慢 | 插件化机制适配，赛季前提前准备 |
| OCR识别错误导致错误建议 | 误导玩家 | 低置信度建议标注"不确定"，关键决策人工确认 |
| 性能不足导致卡顿 | 影响游戏体验 | 降频策略，低配机器自动降级 |
