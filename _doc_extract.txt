   4| 0. 文档定位
   5| 本文件整合此前的产品需求、技术架构和工具/Agent 拆分，作为当前项目的“总纲”。目标不是直接定义一个万能 Agent，而是先构建可验证、可复用、可观测的 TFT Domain Platform，再在其上编排 Coach Orchestrator。
   6| 核心原则：游戏客户端对本系统始终保持黑盒。系统只接收玩家可见的信息（截图、视频帧、摄像头画面及经许可的公开数据），不读取游戏进程内存、不注入、不 Hook、不拦截游戏网络、不修改客户端、不模拟鼠标键盘、不自动执行游戏操作。
   7| 合规原则：“不读内存”只解决技术边界的一部分，不等于获得 Riot 的产品政策许可。Riot 当前 TFT 开发者政策明确不批准动态实时信息、基于当前局面的动态实时建议、实时对手 Scout/预测等场景；赛前静态数据和赛后训练/复盘是明确更适合的方向。正式 Live 能力必须通过独立 Feature Flag 隔离并以当期政策/官方沟通结果为准。
   8| 1. 产品愿景
   9| 将产品构建为“Personal TFT AI Coach”：它不仅能回答版本/阵容/装备问题，还能够理解结构化 GameState，调用知识、规则、统计和模拟工具生成多方案建议，并通过“玩家采用/否定/忽略 + 实际结果”的闭环逐步学习玩家自己的打法。
  10| 第一阶段验证“纯视觉 + 知识 + Agent”能否可靠理解 TFT。
  11| 第二阶段形成赛后逐回合复盘系统。
  12| 第三阶段形成个人打法画像与长期学习。
  13| 第四阶段再评估实时实验能力，并严格受政策与授权约束。

 220| 7. 数据治理
 221| 所有实体使用 Canonical ID，维护各数据源 Source ID 映射。
 222| 所有统计数据强制绑定 Set / Patch / Region / Rank / Queue / CapturedAt / SampleSize。
 223| 所有抓取结果保存 Raw Snapshot，便于回放和发现站点结构变化。
 224| 冲突不自动覆盖：进入 Conflict Queue，由 Source Reliability + Patch Match + Freshness + Sample Size 决定。
 225| Patch 更新时执行受影响实体级联失效或重算。
 226| 所有 Agent 输出必须能够回溯到 Evidence。

 335| 14. 合规与安全边界
 336| 不读取进程内存、不注入、不 Hook、不修改客户端、不拦截网络、不模拟输入。
 337| 生产工程中不引入 ReadProcessMemory、DLL 注入、输入模拟等相关库和能力。
 338| Live Dynamic Recommendation、实时 Opponent Scout、根据当前状态即时改变建议必须独立 Feature Flag，默认关闭。
 339| 研发阶段优先 OFFLINE / POST-GAME / PRE-GAME；正式验证 Live 先遵守 Riot 当前开发者政策并优先使用官方推荐的测试环境。
 340| 任何产品注册、API 使用、数据展示和商业化均需以当前 Riot 政策为准。
 341| Riot 当前 TFT Developer Policy 明确列出：产品需要注册；允许赛前静态数据和训练/赛后分析；不批准 scouting、动态实时信息、动态改变建议并直接处方玩家行为等场景。Riot Vanguard FAQ 说明外部读取游戏内存的工具将不再工作，并建议第三方开发者使用 PBE 验证影响；Riot Terms of Service 同样禁止未经授权的与服务交互的第三方程序及内存读取型信息收集。
 342| 15. 成功标准
 343| 项目成功不以“Agent 会说话”为标准，而以以下闭环打通为标准：
 344| 指定 Patch 的基础知识可稳定查询且有证据链。
 345| 同一实体在多个数据源中能够正确对齐。
 346| 截图/视频能转成可验证的 GameState。
 347| GameState 能被经济/阵容/装备等 Domain Agent 正确消费。
 348| Agent 输出多个方案，并可追溯到规则/统计/历史。
 349| 玩家采用/否定能够完整记录。
 350| 整局能重建并定位关键决策节点。
 351| 累计数据能够形成玩家画像，并改善下一次推荐。

 358| 文档更新：AI Platform V2 / RAG + Cloud LLM
 359| 本次版本更新说明
 360| 本版本基于前一版需求基线，补充“多 Tool + 多 Domain Agent + RAG + Cloud LLM + Personal RAG + Model Router”的完整 AI 平台架构。核心原则保持不变：游戏客户端保持黑盒，系统不读取游戏进程内存、不注入、不 Hook、不拦截游戏网络、不修改客户端、不模拟键鼠、不自动执行游戏操作。Cloud LLM 是增强推理层，不是事实数据库；精确规则、数值、概率必须来自结构化 Tool/Data，RAG 负责召回机制、版本、案例与知识，LLM 负责综合、解释和自然语言交互。
 361| Cloud LLM 与 RAG 总体架构
 362| GameState -> Context Builder -> Structured Tools + Meta + RAG -> Domain Agents -> Decision Optimizer -> Cloud LLM -> Response
 363| Level 0 / Deterministic Tools：规则、概率、状态 Diff、结构化查询。
 364| Level 1 / Retrieval：Structured Query、BM25、Vector Search、Reranker。
 365| Level 2 / Domain Agents：Knowledge、Meta、Economy、Shop、Composition、Item、Transition、Risk、Replay、Personal Coach。
 366| Level 3 / Cloud LLM：综合推理、候选方案比较、反事实解释、自然语言输出。
 367| Cloud LLM 不直接生成 TFT 数值事实，不负责独立计算概率和经济规则。

   6| 1. 产品概述
   7| 产品名称：TFT Vision AI Coach。产品不是传统的“阵容查询器”，而是一个能够理解当前局势、融合版本 Meta、解释多个决策方案，并通过玩家“采用/否定”反馈持续形成个性化策略模型的 AI Coach。

   9| 2. 产品目标与非目标
  10| 2.1 产品目标
  11| 验证纯视觉采集能否在不读取游戏内部状态的情况下还原关键 TFT GameState。
  12| 建立 Patch 感知、来源可信度、数据新鲜度、样本量约束的数据智能层。
  13| 通过 Economy / Composition / Item / Shop / Transition 等 Agent 生成多个候选方案，而非单一指令。
  14| 记录每个关键决策点的 Agent 建议、玩家实际选择、后续结果与最终排名。
  15| 建立玩家风险偏好、阵容偏好、经济风格、常见错误等个人画像。
  16| 支持赛前研究、赛后复盘和离线视频实验，确保即使 Live 模式不可上线，核心产品仍完整。
  17| 2.2 非目标
  18| 不实现任何内存读取、DLL 注入、Hook、网络抓包/拦截、游戏文件修改。
  19| 不自动点击、不自动键盘操作、不自动购买/刷新/升级/装备/站位/选择强化。
  20| 不以绕过 Vanguard、反作弊或 Riot 技术措施为产品目标。

 394| 文档更新：AI Platform V2 / RAG + Cloud LLM
 395| 本次版本更新说明
 396| 本版本基于前一版需求基线，补充“多 Tool + 多 Domain Agent + RAG + Cloud LLM + Personal RAG + Model Router”的完整 AI 平台架构。核心原则保持不变：游戏客户端保持黑盒，系统不读取游戏进程内存、不注入、不 Hook、不拦截游戏网络、不修改客户端、不模拟键鼠、不自动执行游戏操作。Cloud LLM 是增强推理层，不是事实数据库；精确规则、数值、概率必须来自结构化 Tool/Data，RAG 负责召回机制、版本、案例与知识，LLM 负责综合、解释和自然语言交互。

 402| Level 3 / Cloud LLM：综合推理、候选方案比较、反事实解释、自然语言输出。
 403| Cloud LLM 不直接生成 TFT 数值事实，不负责独立计算概率和经济规则。
